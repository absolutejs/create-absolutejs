## 0.20.15 — 2026-11-14

### Changed

- **New projects use @absolutejs/absolute 0.20.0-beta.173**
  AbsoluteJS beta.172 type-checks Vue projects with vue-check, bundled with the framework, on Bun 1.4.4 and newer, and `absolute typecheck` always type-checks even when the project has its own `check` script. Beta.173 stops island pages and Vue lazy routes from exposing server file paths in production, streams React SuspenseSlot and StreamSlot content by default, keeps Angular `@defer` sections after hydration, and fixes dev serving of paths that contain spaces.
- **Vue projects keep vue-tsc only as the fallback for Bun older than 1.4.4**
  `absolute typecheck` checks Vue with vue-check on Bun 1.4.4 and newer. vue-tsc stays in Vue projects because AbsoluteJS still supports Bun 1.4.2, where it is the checker, and `ABSOLUTE_TYPECHECK_CHECKER=tsc` uses it too. The project README says when it can be removed.

### Fixed

- **A route that throws on an HTML or HTMX page renders error.html, and the error is logged**
  server.ts ended with its own `.onError(...)` after the routes. Registered there it never saw their errors, but since AbsoluteJS beta.171 any app `onError` stops the framework rendering `error.html`, so a throwing route answered a browser with a JSON 500 and nothing was logged. The handler also logged a full stack for every 404. server.ts no longer registers one, and HTML and HTMX projects get a `pages/error.html`. A route that throws on a page or HTMX request now renders it with status 500, AbsoluteJS logs the error on the server, and 404s log nothing. Outside development the page shows a generic message and no stack.

## 0.20.14 — 2026-11-13

### Changed

- **New projects use @absolutejs/absolute 0.20.0-beta.171**
  AbsoluteJS beta.171 stops production error pages from showing error text, stops serving /manifest.json, renders error.html when a route throws for HTML and HTMX pages, and fixes React islands, Vue routes and Angular base hrefs under `absolute start`. Backend HMR also keeps scoped state.
- **The HTMX starter creates its scoped state as a top-level `const visitorState`**
  server.ts created `scopedState({ count: { value: 0 } })` inline in `.use([...])`. It is now `const visitorState = scopedState(...)`, passed as `visitorState`. Backend HMR keeps an unchanged top-level const, so visitors keep their counts when server.ts is edited, the form the AbsoluteJS backend HMR docs recommend.

### Fixed

- **`--angular` and `--angular-dir` select Angular, and `--skip` no longer stops at the HTML scripts question**
  `--angular` and `--angular-dir` were silently ignored, so a non-interactive run never made an Angular project. They now work like the other framework flags. `--html --skip` without `--html-scripts` exited with "cannot prompt for --html-scripts"; `--skip` now defaults HTML scripts on, as the prompt does. `--no-html-scripts` still turns them off.
- **The HTML and HTMX starter pages run under `secureHeaders()` without CSP violations**
  The Pages menu opened on hover through inline `onpointerenter` and `onpointerleave` attributes, which the strict CSP from `secureHeaders()` blocks: two violations on each page. The HTML page already handled hover in its script, so the attributes are gone. The HTMX page gets its own `scripts/htmx-example.ts` for it. An HTML page made with `--no-html-scripts` has no script, so its menu opens on click.
- **`absolute typecheck` passes out of the box for Svelte and Vue projects, and the typecheck script runs it**
  The generated `typecheck` script ran plain `tsc --noEmit`, which skips .svelte and .vue files. It now runs `absolute typecheck`. Svelte projects get svelte-check alongside svelte2tsx, and Vue projects get vue-tsc, which `absolute typecheck` needs to check them. Vue projects also get vue-router 4 and Angular projects get @angular/router, for pages that export `routes`.

## 0.20.12 — 2026-11-13

### Changed

- **New projects use @absolutejs/absolute 0.20.0-beta.170, with its production security fixes**
  AbsoluteJS beta.170 fixes production security holes: page props, request context, island state and JSON-LD can no longer break out of their inline scripts, production servers no longer run development code paths or expose stacks on error pages, and the server bundle, SSR bundles and runtime manifests are no longer served as static files. Production servers also start from a read-only build directory, as in a non-root container, and stack traces point at the source. `absolute add` now edits the config this tool generates. Svelte HMR keeps component state, and Svelte pages that use context work under `absolute start`. New opt-in features include `secureHeaders()`, form actions, file routes, internationalization, self-hosted fonts, Web Vitals reporting, HTML includes and cross-framework navigation. The generated starters need no changes: their HTML and HTMX pages have distinct names, and they use no `{#await}` blocks or `pageRouterPlugin`, the two breaking changes and the one removal.

## 0.20.9 — 2026-11-12

### Changed

- **New projects use @absolutejs/absolute 0.20.0-beta.168, and Svelte page props are type-checked**
  AbsoluteJS beta.168 type-checks Svelte page props in server files: `handleSveltePageRequest<typeof Page>({ props })` now fails on a missing, mistyped or unknown prop, as React pages do. Svelte projects install svelte2tsx, which `absolute typecheck` and `absolute dev` use to generate a declaration per component, and their tsconfig lists `.absolutejs/types/svelte` in `rootDirs` so tsc and editors resolve server imports to those declarations. Since beta.145 the framework also refreshes imported CSS and changed images during HMR, builds Svelte and Vue pages without the frameworks a project doesn't use, hydrates islands on HTML and HTMX pages with only `islands.registry`, stops the server `absolute start` started, and no longer imports absolute.config.ts at runtime in production.
